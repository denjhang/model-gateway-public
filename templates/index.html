💡 使用说明 & 关于

📝 使用说明

📍 本地接口（核心用法）

把上方"本地接口信息"的 Base URL 和 API Key 填进任何 OpenAI 或 Anthropic 格式的工具（ZCode、Claude Code、ChatBox、workbuddy 等）即可。双协议全兼容：OpenAI 走 /v1/chat/completions，Claude Code 走 ANTHROPIC_BASE_URL=http://127.0.0.1:8000，同一把 key。渠道挂了自动顺位回落，无感切换。

🔀 路由组（model 填组名即命中）

coding=编程（Claude 系实力优先）；transcribe=转写（按上下文硬排，GPT/1M 优先）；proxy=仅反代渠道；all=全池。也可填具体模型名（支持 渠道/模型 精确指定）。

⚡ 实时调度（热切换）

主页"⚡ 实时调度"卡片按实际出单顺序展示各组：⚡行=真实接单最多者（近15分钟），其后按健康排，故障沉底并标注原因（429/402/熔断剩余时间）。每行显示 延迟 · 上下文窗口 · 总参/激活参数。↑↓/置顶/移除点击即热切换生效，无需重启。组头"↩️ 最近回落"链显示谁失败、为什么、什么时间。

📊 实时监控

上游卡片按路由组分区、组内按实时健康重排（实际首选/顺位/原因标注）。模型表显示可用率、延迟、上下文窗口（点击数字可改）。后台每 5 分钟自动巡检；渠道复活自动回归原排位（免费在前，付费兜底）。

🛡️ 智能容灾（回落守则）

失败按配置序顺位回落，上下文装不下的候选直接跳过（长会话不落小窗口模型）；熔断 60 秒可提前由巡检清除；流中断记失败开熔断，下个请求自动避开。失败原因落 fallbacks.jsonl 供面板展示。

📏 模型规格

总参/激活/上下文窗口已联网查证入库（闭源模型为社区推测，标注来源），面板实时显示，作为强度参考。

📈 消耗统计

按今日/7天/30天统计请求数与 Token，按"渠道·模型"明细；监控台（监控.bat）另有用量排序的最佳前5。
